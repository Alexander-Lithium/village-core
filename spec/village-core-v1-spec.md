# Village Core v1.0 — build specification

**Status:** v1.0.1 (2026-11-13). v1.0.1 clarifies NPC id padding and ordering (A4) after the first independent replication; nothing else changed.
**How to use:** Part A is the one-shot build prompt. Paste all of it, unchanged, into a fresh session of a capable coding model. Part B is the design rationale, for review only (do not paste it).
**Replication target:** two independent builds from Part A, run with the same seed, should produce the **same state hash**. If they don't, the spec is ambiguous somewhere, and the first point where the logs differ shows where.

## A2. Hard rules

1. **All randomness** comes from the seeded streams in A8. Never use `Math.random`, `Date`, `performance.now()` (except to *measure* time), or object-iteration order of untrusted data for decisions.
2. **All state** uses integers or words. No floating-point values in state or decisions (probabilities are compared as integers; see A8).
3. **Iteration order** is always NPC id ascending, unless this spec says to shuffle.
4. **Every behavioural choice** comes from a table lookup (A5–A6) or an explicitly numbered rule in this spec.
5. **Tables are data.** They are loaded from CSV and never hard-coded in `engine.js`. The engine must run with any CSV set that passes validation (A6.0).
6. **Every lookup** is logged (A12).

## A3. Vocabulary (exact strings; lowercase)

- **Level** (traits): `low`, `mid`, `high`. Numeric index for rules: low = −1, mid = 0, high = +1.
- **Temperament traits** (fixed for life): `warmth`, `sociability`, `diligence`, `honesty`, `pride`, `flexibility`.
- **Food tiers** (from integer `food` 0–100; higher = better fed, matching energy): `starving` 0–15 · `very hungry` 16–35 · `hungry` 36–60 · `fed` 61–100.
- **Energy tiers** (from integer 0–100): `exhausted` 0–15 · `very tired` 16–35 · `tired` 36–60 · `rested` 61–100.
- **Mood:** `low`, `calm`, `good`.
- **Liking** (directed, A toward B): `dislike`, `neutral`, `like`, `close`.
- **Belief pairs** (each NPC holds exactly one pole of each pair):

| Pair | Positive pole | Negative pole |
| --- | --- | --- |
| `trust` | `people mean well` | `people are against me` |
| `worth` | `i am respected` | `i am overlooked` |
| `effort` | `hard work pays off` | `nothing i do matters` |

- **Belief tier:** `faint`, `held`, `core`.
- **Belief position** (for metrics): a pair is a six-step ladder: −3 = core negative, −2 = held negative, −1 = faint negative, +1 = faint positive, +2 = held positive, +3 = core positive. (No zero.)
- **Rooms:** `home`, `field`, `square`.
- **Needs:** `none`, `eat`, `rest`, `eat now`, `rest now`.
- **Stances:** `friendly`, `neutral`, `cold`, `hostile`.
- **Acts** (what an initiator does), allowed per room:
  - field: `help`, `chat`, `take credit`, `argue`
  - square: `chat`, `praise`, `share food`, `interrupt`, `ignore`, `argue`
- **Events** (what the receiver experiences), and which belief pair appraises them:

| Act | Event received | Pair | Valence |
| --- | --- | --- | --- |
| help | `helped` | trust | positive |
| chat | `chatted with` | trust | positive |
| share food | `shared food with` | trust | positive |
| argue | `argued with` | trust | negative |
| interrupt | `interrupted` | trust | negative |
| (apology, A10.4) | `apologised to` | trust | positive |
| praise | `praised` | worth | positive |
| ignore | `ignored` | worth | negative |
| take credit | `credit taken` | worth | negative |
| (end of day, A11.1) | `work went well` | effort | positive |
| (end of day, A11.1) | `work went badly` | effort | negative |

- **Negative acts** (create an apology debt, A10.5): `argue`, `interrupt`, `ignore`, `take credit`.
- **Meanings:** `good sign`, `nothing much`, `slight`, `insult`.
- **Belief pressure** (relative to the pole the NPC currently holds): `stronger` (confirms it), `same`, `weaker` (contradicts it), `strained` (contradicts a *core* belief). Constraints: at `core` the only allowed pressures are `same` and `strained`; at `faint` and `held` the only allowed pressures are `stronger`, `same`, `weaker`.
- **Liking change:** `up`, `same`, `down`.
- **Grudge responses:** `let it go`, `cool off`, `hold grudge`, `pay back`.
- **Apology decision:** `apologise`, `don't`.
- **Evidence balance:** `mostly against`, `mixed`, `mostly for`, `strongly for`.
- **Integration moves:** `stay`, `up`, `down`, `flip`, `break`.
- **Trait step:** `-1`, `0`, `+1`.

## A4. State

**Per NPC** (id = `n` followed by the NPC's number zero-padded to 4 digits: `n0001`, `n0002`, …, `n9999`, `n10000`; **id order always means numeric order of that number**, never string order):
- `temperament`: six traits → level.
- `beliefs`: per pair → `{pole, tier}`.
- `effective`: `warmth`, `sociability`, `diligence`, `pride` = temperament index + sum of compile steps (A6, T12) over the NPC's three beliefs, clamped to −1..+1, then mapped back to a level. `honesty` and `flexibility` are always the temperament values.
- `food`, `energy`: integers 0–100; higher = better for both. Start: food 80, energy 80.
- `mood`: start `calm`.
- `room`: current room.
- `fieldTicksToday`: integer.
- `todayPressure`: per pair, the list of pressures received today.
- `buffer`: per pair, a list of up to 7 integers (one per past day; newest last). Daily value = the **sign** (−1, 0 or +1) of (number of `stronger`) − (number of `weaker`) − (number of `strained`): each day casts one vote.
- `gotEvent`: boolean, whether the NPC received an event this hour (not part of the canonical state).
- `rel`: map from other NPC id → `{liking, counter, grudge, offence, owesApology, workedBesideToday}`:
  - `liking`: start `neutral`; `counter`: integer, start 0.
  - `grudge`: `none`, `cool off`, `hold grudge`, `pay back`; start `none`.
  - `offence`: `none`, `slight`, `insult`: the most recent unresolved offence this NPC *received* from the other.
  - `owesApology`: boolean (this NPC owes the other an apology).
  - `workedBesideToday`: boolean.
  - Relationships exist for every pair of NPCs in the same hamlet (A11.4), created at start.

**Global:** `day` (0-based), `hour` (0–15), `tick` = day × 16 + hour.

## A5. Table format and lookup

- One CSV per table, UTF-8, comma-separated, first line = header, no quoting needed (no field contains a comma). Input columns come first, then output columns, with **exactly** the headers in A6.0b.
- File names: `T1_needs.csv`, `T2_action.csv`, `T3_stance.csv`, `T4_act.csv`, `T5_apology.csv`, `T6_appraise_trust.csv`, `T7_appraise_worth.csv`, `T8_appraise_effort.csv`, `T9_mood.csv`, `T10_grudge.csv`, `T11_integration.csv`, `T12_compile.csv`. A table directory contains all twelve (designer tables are copied into every directory).
- Belief columns use the full belief text (e.g. `people are against me`).
- **Key** = input values joined with `|` in column order (e.g. `friendly|square|high`). Store each table in a `Map` from key → output object.
- **Lookup:** exact key → row. If missing, use the table's **default** (A6) and record the key in `missingRows` (logged, counted in the run summary). No other fallback.
- **Two-option tables** (T2, T4) have outputs `first`, `second`. Choose `first` unless the stream draws below the second-option threshold: `draw(100) < 25` → `second`. T2 draws from the `room` stream, T4 from the `act` stream (A8). The threshold (25) is a config parameter `pSecond`.

## A6. Tables

`teacher` = filled by a teacher LLM in experiments (the engine ships with rule-based baselines); `designer` = fixed by this spec in all conditions.

### A6.0 Validation (run at load; refuse to run on failure)
- Every combination of input values is present exactly once (full grid). No extra rows.
- Every output value is from the allowed list for that column.
- T4: both acts allowed in the row's room.
- T6–T8: pressure constraints hold (no `stronger` at core; `strained` only at core).
- Compute and store SHA-256 of each table's **normalised text**: the header line, then each row's values joined by `,`, rows sorted by key in plain string (UTF-16 code-unit) order, every line followed by `\n`. `gen_rule_tables.js` writes files in exactly this normalised form.

### A6.1 Rules that generate each table
`gen_rule_tables.js` writes **every** table from these rules. The designer tables (T1, T11) are always these rules. The teacher tables generated this way are the **rule baseline** ("hand-written rules" condition). Let `i(x)` = level index (−1/0/+1). Liking index: dislike −1, neutral 0, like +1, close +2. Mood index: low −1, calm 0, good +1.

- **T1 needs:** first match wins: food `starving` → `eat now`; energy `exhausted` → `rest now`; food `very hungry` → `eat`; energy `very tired` → `rest`; food `hungry` and energy `tired` → `eat`; otherwise → `none`.
- **T2 action:** if need is `eat` or `rest`: first `home`; second `field` if diligence is `high`, else `square`. If need is `none`: field score = i(diligence), square score = i(sociability); first = room with the higher score (tie → `field`); second = the other room, except if both scores are −1, second = `home`.
- **T3 stance:** s = i(warmth) + liking index + mood index. s ≥ 2 → `friendly`; s = 0 or 1 → `neutral`; s = −1 → `cold`; s ≤ −2 → `hostile`.
- **T4 act** (first / second):
  - field: friendly → `help` / `chat`; neutral → `chat` / `help`; cold → `chat` / `take credit` if honesty is `low`, else `chat` / `chat`; hostile → `argue` / `take credit` if honesty is `low`, else `argue` / `chat`.
  - square: friendly → `praise` / `share food`; neutral → `chat` / `ignore` if honesty is `low`, else `chat` / `chat`; cold → `ignore` / `interrupt`; hostile → `argue` / `interrupt`.
- **T5 apology:** i(honesty) − i(pride) ≥ 0 → `apologise`; else `don't`.
- **T6–T8 appraisal.** Let v = event valence (A3) and p = the held pole's sign (+ for positive pole).
  - **Small talk:** `chatted with` → `nothing much`, `same`, `same` in every row (routine contact is not evidence). The rules below apply to all other events.
  - **Confirming** event (v matches p: positive event under a positive pole, or negative under a negative pole): pressure `stronger` (core → `same`). Meaning: positive event → `good sign`; negative event → `slight` at faint, `insult` at held or core.
  - **Contradicting** event: pressure `weaker` (core → `strained`). Meaning: positive event → `good sign` at faint, `nothing much` at held or core; negative event → `slight`.
  - **Pride (T7 only, negative events only):** if pride is `high`, raise the meaning one step (`nothing much` → `slight` → `insult`); if pride is `low`, lower it one step (`insult` → `slight` → `nothing much`).
  - **Liking change (T6, T7):** `good sign` → `up`; `nothing much` → `same`; `slight` or `insult` → `down`.
- **T9 mood:** `good sign` → one step up (cap `good`); `nothing much` → unchanged; `slight` → one step down (floor `low`); `insult` → `low`.
- **T10 grudge:** g = i(warmth) + (1 if apology `received`) − (1 if offence `insult`). g ≥ 1 → `let it go`; g = 0 → `cool off`; g = −1 → `hold grudge`; g ≤ −2 → `pay back`.
- **T11 integration:**
  - `strongly for`: faint → `up`, held → `up`, core → `stay`.
  - `mostly for`: if flexibility `high`: faint/held → `up`, core → `stay`; otherwise `stay`.
  - `mixed`: `stay`.
  - `mostly against`: faint → `flip` (flexibility `low` → `stay`); held → `down` (flexibility `low` → `stay`); core → flexibility `high` → `break`, `mid` → `down`, `low` → `stay`.
- **T12 compile** (steps listed; unlisted = 0):
  - `people mean well`: held warmth +1; core warmth +1, sociability +1.
  - `people are against me`: held warmth −1; core warmth −1, sociability −1.
  - `i am respected`: core pride +1.
  - `i am overlooked`: held sociability −1; core sociability −1, pride +1.
  - `hard work pays off`: held diligence +1; core diligence +1.
  - `nothing i do matters`: held diligence −1; core diligence −1, sociability −1.
  - All faint rows: all 0.

## A7. Moves on the belief ladder (applied at night, A11.2)
- `up`: faint → held → core.
- `down`: core → held → faint.
- `flip`: faint of one pole → faint of the opposite pole.
- `break`: core of one pole → faint of the opposite pole.
- `stay`: no change.
- A move that doesn't apply (`up` at core, `down` at faint, `flip` not at faint, `break` not at core) causes no change.
After any move that changes the belief, clear that pair's `buffer`.

## A8. Randomness
- **Generator:** mulberry32 (32-bit). `next()` returns an unsigned 32-bit integer. `draw(n)` = `next() % n`.
- **Streams:** one independent generator per purpose. Its seed = FNV-1a 32-bit hash of the UTF-8 string `"<runSeed>:<streamName>"`. Streams: `meet`, `room`, `act`, `work`, `shuffle`, `random`. (Room and act choices use separate streams so that a change in acts, e.g. an apology replacing an act, can never change who goes where or who meets whom.) The cast uses its own seed (A9).
- **Fisher–Yates shuffle** (in place, i from length−1 down to 1, j = draw(i+1), swap).
- Draws are consumed only where this spec says, in the order it says.

## A9. Cast generator
- Seed string `"cast:<castSeed>"` (FNV-1a → mulberry32), one stream, used in this order for NPC 1..N:
  - For each temperament trait in A3 order: level = [low, mid, high][draw(3)].
  - For each pair in order trust, worth, effort: pole = draw(2) == 0 ? positive : negative; tier from r = draw(100): r < 50 faint, r < 85 held, else core.
- Write as CSV: `id,warmth,sociability,diligence,honesty,pride,flexibility,trust_pole,trust_tier,worth_pole,worth_tier,effort_pole,effort_tier`.
- Reference casts: `castSeed = 1`, N = 20 (`cast/cast_s1_n20.csv`). The 5-NPC cast = the first 5 rows of that file. Large casts (A11.4) are generated on the fly with castSeed = 1.
- The cast is independent of the run seed: the same characters start every run.

## A10. One waking tick (hour 0–15), in this exact order

0. **Reset:** `gotEvent` = false for every NPC.
1. **Body.** For each NPC: food −= 5 (floor 0); energy −= 6 if the NPC was in the field last tick, else −= 4 (floor 0). (Hour 0 uses the room from the end of the previous day, which is always `home`.)
2. **Needs.** need = T1(food tier, energy tier).
3. **Room choice.** If need is `eat now` or `rest now`: room = `home` (no lookup). Otherwise room = T2(need, diligence, sociability) via the two-option rule (one `room` draw).
4. **Home effects.** For NPCs at home: if need is `eat` or `eat now`: food += 40 (cap 100); if need is `rest` or `rest now`: energy += 15 (cap 100); if need is `none`: energy += 5.
5. **Field count.** For NPCs in the field: `fieldTicksToday` += 1.
6. **Encounters.** For each hamlet (ascending), for each room in order `field`, then `square`:
   1. Occupants sorted by id; Fisher–Yates shuffle with `meet`; pair positions (0,1), (2,3), …; an odd last NPC has no encounter.
   2. For each pair in order: initiator = first of the pair if `draw(2)` (from `meet`) is 0, else second. Call them I and R.
   3. **Worked beside** (field only): if not already set today, set `workedBesideToday` both ways. (No liking effect in v1.)
   4. **Apology check:** if I `owesApology` to R: decision = T5(I.honesty, I.pride). If `apologise`: clear I's debt to R; R receives the event `apologised to` (step 6); then go to the next pair (no act this encounter). If `don't`: continue to step 5.
   5. **Act.** If I's grudge toward R is `pay back`: stance = `hostile` and set that grudge to `hold grudge`. Otherwise stance = T3(I.warmth, I's liking toward R, I.mood). Act = T4(stance, room, I.honesty), two-option rule (one `act` draw). If the act is negative, set I `owesApology` to R.
   6. **Appraisal by R.** Look up the event's pair table (T6/T7/T8) with R's held pole and tier for that pair (and R.pride for T7) → meaning, pressure, liking change. Then:
      - Set R.gotEvent = true.
      - Append pressure to R.todayPressure[pair].
      - R.mood = T9(R.mood, meaning).
      - Liking change on R → I (A10.7): `up` → +1 (ignored if R's grudge toward I is `hold grudge` or `pay back`); `down` → −1; `same` → 0. If R's grudge toward I is `cool off`, the change is −1 instead of `same` or `up`.
      - If meaning is `slight` or `insult`: R's offence toward I = meaning; R's grudge toward I = T10(R.warmth, meaning, `none`), and `let it go` stores `none`.
      - If the event is `apologised to` and R's offence toward I is not `none`: R's grudge toward I = T10(R.warmth, offence, `received`) (`let it go` stores `none`); then R's offence toward I = `none`.
7. **Liking counter rule.** Applies whenever a counter changes: if counter ≥ +3 → liking one step up (cap `close`), counter = 0; if counter ≤ −3 → liking one step down (floor `dislike`), counter = 0.
8. **Quiet-hour mood fade:** every NPC with `gotEvent` false moves mood one step toward `calm`. (A mood lasts while things keep happening and fades after a quiet hour.)
9. **Log** (A12).

## A11. Night (after hour 15), in this exact order

1. **Work outcome.** For each NPC with `fieldTicksToday` ≥ 4: chance of `work went well` by **effective** diligence: low 35, mid 50, high 65; `draw(100) < chance` (stream `work`) → `work went well`, else `work went badly`. Appraise with T8 (pressure into todayPressure; mood via T9). No liking change.
2. **Integration** (skip if `loopOff`). For each NPC and pair: append today's value (A4: the sign of today's net pressure) to the buffer (drop the oldest if > 7 entries). balance = sum of the buffer: ≤ −2 `mostly against`; −1..+1 `mixed`; +2..+4 `mostly for`; ≥ +5 `strongly for`. Move = T11(balance, tier, flexibility); apply it (A7).
3. **Recompile** effective traits (A4) (skip if `loopOff`).
4. **Grudge decay.** Every `cool off` grudge becomes `none`.
5. **Mood:** one step toward `calm`.
6. **Body:** energy += 60 (cap 100); food −= 10 (floor 0); room = `home`.
7. **Reset:** `fieldTicksToday` = 0, `todayPressure` emptied, `workedBesideToday` cleared.
8. **Snapshot** (A12).

### A11.4 Hamlets (scale)
NPCs are grouped by id into hamlets of `hamletSize` (default 20; the last hamlet may be smaller). Rooms are per hamlet: NPCs meet only others in their own hamlet, and relationships exist only within a hamlet. A 5- or 20-NPC run is one hamlet.

## A12. Logs and outputs

- **Decision log** (one line per lookup, in the order lookups happen): header `tick,npc,table,key,output,choice`, then one line per lookup. `tick` = the tick number for waking lookups, `night<day>` for night lookups, `start` for the initial compile. `table` = the T-number (e.g. `T3`). `key` = the lookup key. `output` = all output values of the row used, joined by `|`. `choice` = `first` / `second` for T2 and T4, `-` otherwise. Every line is followed by `\n`. Toggleable (off for large runs; the log hash is then `-`).
- **Initial compile:** before the first tick, compute effective traits for every NPC (T12 lookups, logged with tick `start`).
- **Event log:** `tick,room,initiator,receiver,act,event,meaning,pressure,likingChange`.
- **Daily snapshot** (after night): per NPC: belief positions (trust, worth, effort) and effective traits after the night step, and mood at the end of hour 15; plus a list of moves applied that night.
- **Run summary (JSON):** config; cast hash; each table's hash; `missingRows`; final **state hash** = SHA-256 of the **canonical state text** (below); **log hash** = SHA-256 of the full decision log text; daily metrics (below); timing (ms per tick, total).
- **Canonical state text:** one line per NPC in id order, lines joined by `\n` (no trailing newline):
  `<id>|food=<n>|energy=<n>|mood=<mood>|room=<room>|trust=<belief>/<tier>|worth=<belief>/<tier>|effort=<belief>/<tier>|eff=<warmth>,<sociability>,<diligence>,<pride>|buf=<trust buffer>;<worth buffer>;<effort buffer>|rel=<rel list>`
  where each buffer is its integers joined by `,` (empty if none), and the rel list is, for each other NPC in the hamlet in id order, `<otherId>:<liking>:<counter>:<grudge>:<offence>:<owesApology 0/1>` joined by `;`.
- **Cast hash** = SHA-256 of the cast CSV text (header + rows, every line followed by `\n`).
- **Daily metrics:** count of each event (including night work outcomes); mood counts at the end of hour 15; per pair, count of NPCs at each belief position; moves by type (`up`/`down`/`flip`/`break`); friendships (pairs with mutual `like` or `close`); feuds (pairs with mutual `dislike`); isolates (NPCs with no `like`/`close` toward anyone and none toward them).

## A13. Run configuration and command line
Config fields (with defaults): `runSeed` 1 · `castSeed` 1 · `n` 20 · `days` 30 · `hamletSize` 20 · `pSecond` 25 · `tableDir` `tables/rules` · `loopOff` false · `traitsOff` false · `tablesMode` `csv` · `logDecisions` true · `skipValidation` false (tests only).
- `traitsOff`: after loading the cast, set every temperament trait to `mid` (beliefs unchanged).
- `tablesMode`: `csv` (as loaded) · `shuffled` (for each teacher table in T-number order: sort its keys; group the keys (T4 by room, T6–T8 by tier, other tables one group), groups in order of first appearance among the sorted keys; within each group, list the output sets in key order, Fisher–Yates shuffle that list with `shuffle`, and assign it back to the keys in key order) · `random` (for each teacher table in T-number order, each key in sorted order, each output column in column order: value = allowed[draw(allowed.length)] from `random`, where `allowed` is that column's values in A3 order, restricted for T4 to the row's room and for T6–T8 pressure to the row's tier).
- `run.js` usage: `node run.js --runSeed 1 --n 20 --days 30 --tableDir tables/rules [--loopOff] [--traitsOff] [--tablesMode shuffled] [--seeds 1-100] --out results/<name>`. With `--seeds a-b`, run each seed and write one summary per seed plus a combined CSV of final metrics.

## A14. Viewer (`viewer.html`)
Self-contained page (no network). Controls: run seed, n (5/20), days, table set, loopOff, traitsOff, tablesMode; Run, Step (one tick), Play/Pause. Shows: three room panels per hamlet with NPC dots labelled by id; a side panel for the selected NPC (temperament, effective traits, beliefs, mood, body, liking toward others, last 10 decision-log lines as readable traces "inputs → table → output"); a line chart of belief positions per pair over days (mean and per-NPC lines); the summary hashes; a download button for logs and summary. With n = 1,000–10,000, hide the dots and show only metrics and timing.

# PART B — DESIGN RATIONALE (for review; not pasted)

Each decision: **what**, **why**, and **where to push back** if you disagree. Items marked ⚠ change §12.1 of engine-architecture and are logged in the change log.

## B1. Overall shape
- **One exact spec, built in one shot.** The engine is fully specified down to random-number algorithms and step order, so independent builds should give identical hashes. That turns "replicable" into a concrete test: build twice in fresh sessions and compare golden hashes. *Pushback:* this makes the prompt long and dense. A looser spec would be easier to read but would only replicate approximately.
- **Rule tables included.** The builder writes every table from short written rules. They serve three purposes: they let the engine be tested before any teacher fills; they are the "hand-written rules" arm of the three-brain comparison (§12.3 item 5) at no extra cost; and they give a baseline that teacher tables must beat. *Pushback:* the rules are mine, so the hand-written arm reflects my judgement. Equally, it's a transparent baseline that anyone can read.
- **Designer vs teacher tables.** Needs (T1) and integration (T11) are fixed by the spec in every condition. The other ten are filled by teachers. Reason: needs are bookkeeping, and §3 of your doc names integration rules as the game-design lever ("how fast beliefs move"), not psychology. Keeping them fixed means teacher arms differ only in psychology. *Pushback:* integration could be teacher-filled too, which would make "every arrow a table" literally true. That costs 36 more rows per fill, and teacher differences would then mix psychology with pacing.

## B2. Character
- ⚠ **Six temperament traits, not seven.** I dropped nerve and ambition and added pride. Rule used: a trait stays only if some table reads it. The village has no danger (nerve) and no hierarchy or promotion (ambition). Pride is read by the worth appraisal and by apology, and §12.1 already lists pride as an appraisal input without listing it as a trait. *Pushback:* add ambition back if you want "take credit" to depend on it rather than honesty. That adds rows to T4.
- **Three levels per trait (low/mid/high).** As in §12.1. Five levels would multiply rows (T7 alone would go from 54 to 150).
- ⚠ **Three belief pairs instead of "4 self-beliefs from a small library".** Each NPC holds one pole of each pair: trust, worth, effort. Every event is appraised by exactly one pair, so every belief is fed by events, and no belief sits there unused. Pairs make arcs concrete: a broken core belief is replaced by its opposite (§3 "replaced from the library"), so an arc is a measurable jump on a six-step ladder. *Pushback:* a fourth pair (e.g. belonging) needs events that feed it, and every event added grows the appraisal tables.
- **Effective traits = temperament + belief steps, clamped.** This keeps temperament fixed ("the story can't overwrite genes", §2) while beliefs shift behaviour. Honesty and flexibility never shift. *Pushback:* clamping means a high-warmth NPC with a core "people are against me" only drops to mid. That's intended, but it limits how far arcs can go.

## B3. World and time
- **16 waking hours + night, three rooms.** As in §12.1. Home has no social encounters (everyone lives alone). Socialising happens only in the field and the square. *Pushback:* shared homes (families) are a natural later extension, but they bring relationships with structure.
- **Body numbers (food −5/hour, eating +40, etc.).** Food counts up (100 = full) so that producing food later fills it, and both body values read "higher = better". Chosen so the rule-table villagers eat about twice a day and nobody starves (test 8). These are ordinary game-balance constants, disclosed, and candidates for sensitivity analysis.
- ⚠ **Events trimmed from 12 to 11, changed.** Removed `harmed` (vague, overlaps argue), `promised` and `broke a promise` (they need memory of who promised what, which is the variable-binding problem §8 lists as a limit). Added `chatted with` (a neutral-positive act; otherwise every encounter is loaded), `ignored` and `interrupted` stay, `apologised` becomes a separate repair step, and work outcomes became events (`work went well/badly`) so the effort belief has evidence. `worked beside` is no longer appraised; it only nudges liking.
- **Hamlets of 20 for scale.** At 10,000 NPCs, everyone meeting everyone is unrealistic and would make relationships the bottleneck (§11 caps circles at about 150). Hamlets keep per-NPC work constant, which is the honest version of the scaling claim. *Pushback:* the stress test then shows that "many villages run cheaply", not that "one huge village works". Making hamlets overlap would be a later step.

## B4. Decisions and the loop
- **Two-option tables with a 75/25 split.** For room choice and acts, the teacher gives a first and second choice. Without this, identical people in identical states always act identically, and the only variety comes from who meets whom. 25% is arbitrary, so it's a config parameter for sensitivity analysis. It replaces §12.1's vaguer "small decision noise as a meta-trait". *Pushback:* making the 25% depend on a trait (impulsiveness) would turn noise into personality.
- **Social act → appraisal → mood/liking/grudge, one act per encounter.** The receiver doesn't reply in the same hour, which keeps the order of operations unambiguous. They may meet again next hour.
- **Apology as debt.** A negative act creates a debt. The next time the pair meets, the debtor's apology table decides whether to apologise, and the receiver re-runs the grudge table with "apology received". This makes the grudge table's apology column real without free-form memory.
- **Integration = rolling 7-day evidence balance.** This implements "evidence counts" and "a week of slights → held" from the Gus example (§3). Thresholds (±2, +5) and the 7-day window are parameters.
- **Flexibility = narrative inertia.** Low-flexibility NPCs need strong evidence to change and can't break a core belief. High-flexibility NPCs move on milder evidence and can break. This is the meta-trait from §2/§4.
- **"Success doesn't touch the wound" is NOT in the rule baseline.** In the rules, kind events strain a core grievance like any contradiction. If teacher fills produce the wound rule on their own, as the contamination test suggests they might, that is a finding. Putting it in the baseline would pre-load the result.

## B5. Rigour features
- **Separate random streams.** Meetings, choices, work luck and table shuffling each have their own generator. Changing a table then can't change who meets whom, which is what makes the one-row-edit test (§12.3 item 6) and the arm comparisons clean (test 4).
- **Integer-only state, pure-JS SHA-256.** Floating-point and platform crypto can differ between browsers and phones; integers and a bundled hash can't.
- **Null models built in:** `loopOff`, `traitsOff`, `shuffled` tables, `random` tables. If shuffled tables give the same friendships and feuds as real tables, the structure comes from the room and meeting setup, not from the tables' psychology.
- **Fixed cast, separate cast seed.** The same 20 characters start every run, so differences across run seeds are lives diverging, which is what §12.3 item 1 measures.

## B6. Not in v1 (deliberately)
- **Blending between neighbouring rows (§1 fuzzy trick):** all inputs are discrete words, so there are no cliff edges to smooth.
- **Gossip, planning, reflection table, the narrative LLM updater, structured narratives with key scenes:** later experiments build on this core.
- **Hooks for later experiments** (suture: another NPC's tables choose the act; live-LLM arm: export each tick's situation as a prompt and import the chosen acts). I left these out of v1 to keep the core small. They can be added as v1.1 without changing v1 results. *Pushback:* specifying the hooks now avoids changing the engine later. My preference is to add each when its experiment is designed.

## B8. Calibration of v1 (done before any teacher data; disclosed)
The first build, with the rule tables, produced a degenerate village. By day 10 every villager was in a good mood, 16/20 held "people mean well" at core, and by day 30, 186/190 pairs were friends, identical across seeds. Four **mechanism** fixes were made, each for a stated reason. No numeric parameter was tuned.
1. **Small talk is routine** (rule tables only): `chatted with` is `nothing much` and isn't evidence. Before this, the most common act counted as a kindness, so kindness was everywhere.
2. **Evidence is one vote per day** (sign of the day's net pressure). Before this, roughly 8 encounters a day swamped the weekly thresholds, so beliefs rose a tier almost every night. "A week of slights → held" now means days, not encounters.
3. **Mood fades after a quiet hour.** Before this, one good event kept a villager in a good mood all day, making every later encounter friendlier (a within-day ratchet). Resetting mood every hour was tried and rejected, because a mood would then never reach the next encounter and the mood table would do nothing.
4. **Worked beside has no liking effect.** Before this, everyone in the shared field reached `like` within days through familiarity alone, which drove the rest of the cascade.
A fifth fix came from acceptance test 4: room and act choices originally shared one random stream, so a changed act (via an apology) shifted later room choices and meetings. They now use separate streams.

Resulting rule-table village (20 NPCs, 30 days, 20 seeds; exploratory): friendships mean 20.6 of 190 pairs (range 15–28), feuds 0.7 (0–3), isolates 0.6, belief flips 28.8 and core breaks 12.8 per run. For orientation only: loop off gives 14.4 friendships and 6.6 feuds; shuffled tables give 9.6 friendships and 7.3 feuds with a much wider range. These are not experiment results.
